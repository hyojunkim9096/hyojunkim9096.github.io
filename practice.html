Python · LLM · RAG · LangChain · Claude Code · Codex · ChatGPT APIAI 기능 개발과 AI 에이전트를 활용한 개발. LLM, RAG, LangChain으로 문서 요약 챗봇과 AI 에이전트를, 그리고 답안지를 읽어 채점하는 도구를 만들었습니다.

Jenkins는 운영 환경에서 빌드와 배포에 쓴 경험이 있습니다. 설치와 파이프라인 구축은 하지 않았습니다.

AI 팀을 짜고, 돌려 보고, 고쳐 가며 만듭니다.

AI를 도구로 쓰는 데서 그치지 않고, 여러 AI 에이전트(30개 이상)를 한 팀처럼 운영해 개발합니다. 설계, 구현, 검토, 검증을 서로 다른 AI가 맡고 결정은 사람이 합니다. 팀은 한 번 짜고 끝내지 않고, 결과를 재어 가며 계속 다시 짭니다.

  1. 정리목표 · 범위 · 위험 · 완료 기준
  2. 설계판단은 큰 모델에
  3. 구현반복 작업은 빠른 모델에
  4. 검토 · 보안다른 AI가 서로 대조
  5. 증거시험과 화면 확인
  6. 사람이 결정마지막 판단은 직접

이렇게 운영합니다

역할을 나눕니다

총괄 AI 하나가 일을 나누고 검사와 반영만 맡고, 직접 코드를 쓰지 않습니다. 그 아래에 일감을 나누는 PM 셋, 메뉴 묶음마다 화면과 서버를 함께 맡는 팀, 디자인 팀장, 공용 부품을 맡는 창, 화면을 찍어 판정하는 창을 따로 둡니다.

서로 다른 AI가 교차 검토합니다

Claude로 만들고, 다른 회사의 AI인 Codex가 검토하고 검증합니다. 보안 설계는 따로 둔 AI가 최종 판단만 합니다.

검사를 통과한 것만 하루 네 번 반영합니다

06 · 12 · 18 · 24시에 검사를 통과한 것만 모아 개발 서버에 반영합니다. 반영 전에 자동 검사와, PC · 핸드폰 두 폭의 화면 그림 확인을 거칩니다. 판마다 화면 시험 34,308개와 서버 시험을 돌립니다.

30분마다 점검합니다

쉬는 팀을 깨우고 막힌 일을 풀고, 쓰는 속도와 비용을 재서 일을 더 주거나 늦춥니다.

팀을 계속 다시 짭니다

처음에는 큰 팀으로 시작해 일하는 창 넷의 작은 팀으로, 지금은 메뉴 묶음마다 화면과 서버를 한 팀으로 묶고 PM이 통제하는 꼴로 바꿔 왔습니다. 비싼 모델은 총괄 하나만 쓰고 짓는 창은 가벼운 모델로 바꿨습니다. 속도 · 비용 · 실수를 재서 바꿉니다.

실수를 규칙으로 만듭니다

사고는 원장에 적고, 되풀이되면 번호 붙은 규칙으로 만들어 모든 AI가 지킵니다. 지금 규칙은 33개입니다. 대표가 내린 결정도 원장에 번호를 붙여 쌓고, AI는 일하기 전에 그 원장부터 찾아봅니다.

마지막에 켜는 것은 사람입니다

운영 배포, 실제 문자 발송, 실제 키, 외부 공개는 AI가 하지 않고 사람이 마지막에 켭니다.

일하는 원칙

증거로 닫습니다

AI가 「됐다」고 해도 시험과 화면 확인으로 증거가 나와야 끝냅니다.

일에 맞는 모델을 씁니다

동시에 도는 에이전트 수와 사용 한도를 보며 비용을 관리합니다.

시작 전에 정리합니다

목표, 범위, 위험, 완료 기준을 먼저 적고 시작합니다. 중간에 고치느라 늦어지는 일을 줄입니다.

장애는 세 단계로 풉니다

빠른 임시 조치로 먼저 멈추고, 로그와 DB로 원인을 찾고, 다시 생기지 않게 근본을 고칩니다.

현업과 직접 이야기합니다

요구사항 정의부터 오픈까지 담당자와 직접 맞춥니다. 바뀌는 요구에도 빨리 따라갑니다.
